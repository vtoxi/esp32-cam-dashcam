# MPU6050 (HW-123 / GY-521 layout) — Wiring

**Status: Sensor-side pinout confirmed from photo; gateway-side GPIO proposed
(untested).** Physical unit is silkscreened `HW-123`, chip marked `ITG/MPU`, with 8 pins
in order: `VCC, GND, SCL, SDA, XDA, XCL, AD0, INT` — same functional layout as the
generic GY-521 breakout this document originally described. Gateway-side pins proposed
in `docs/wiring/ESP32_S3_GATEWAY.md` (GPIO 8/9) pending bench verification.

## 1. Module Description

HW-123 breakout (functionally identical to GY-521): InvenSense MPU6050 6-axis
accelerometer + gyroscope, I2C interface.

## 2. Voltage Requirements

- VCC: 3.3V–5V (GY-521 has an onboard 3.3V regulator on most variants — verify against
  the physical unit).
- I2C logic: 3.3V (regulated onboard) — generally safe to connect directly to ESP32 I2C
  pins, but confirm the specific breakout has the regulator/level-shifting populated.

## 3. Pin Table

| Pin | Connects to |
|---|---|
| VCC | 3.3V or 5V (per board regulator — verify) |
| GND | Common ground |
| SCL | ESP32-S3 gateway GPIO 9 (proposed I2C SCL) — see `docs/wiring/ESP32_S3_GATEWAY.md` |
| SDA | ESP32-S3 gateway GPIO 8 (proposed I2C SDA) — see `docs/wiring/ESP32_S3_GATEWAY.md` |
| XDA / XCL | Not used (auxiliary I2C master pins, for daisy-chaining another sensor — not needed here) |
| AD0 | Leave low/unconnected for default address `0x68`; pull high for `0x69` if an address conflict arises |
| INT | Not used initially (optional interrupt pin for motion-detection wake, may be used in Phase 17 low-power work) |

## 4. ESP32 GPIO Connection

Proposed: gateway GPIO 8 = SDA, GPIO 9 = SCL (primary I2C bus, shared with one SSD1306 —
see `docs/wiring/SSD1306.md` for the dual-OLED address-conflict resolution). No address
conflict with either OLED expected (`0x68` vs `0x3C`). Not yet bench-verified.

## 5–6. Power / Ground

Per Pin Table above; common ground with gateway required.

## 7. Communication Interface

I2C, default address `0x68` (AD0 low) or `0x69` (AD0 high).

## 8. Pull-ups / Pull-downs

I2C requires pull-ups on SDA/SCL (typically 4.7kΩ) — many GY-521 breakouts include
onboard pull-ups; if sharing a bus with SSD1306 (which may also have onboard pull-ups),
verify total pull-up strength isn't too low (too many parallel pull-ups can over-load the
bus drive) — usually fine with just 2 devices but worth checking against measured bus
levels once assembled.

## 9. Known Conflicts

None expected beyond the shared-bus check above.

## 10. Safety Warnings

None specific beyond standard I2C/3.3V logic precautions.

## 11. Testing Procedure

1. Run an I2C scanner sketch, confirm device responds at `0x68`.
2. Run a minimal MPU6050 library example, confirm plausible accelerometer/gyro readings
   at rest (~1g on Z axis, ~0 on X/Y, gyro near 0 on all axes).
3. Test with the SSD1306 also on the bus to confirm no address/bus conflict.

## 12. Example Configuration

Deferred to Phase 9 firmware implementation.

## 13. Board-Specific Differences

"HW-123" is a common relabeling of the same MPU6050 breakout design as GY-521 — pinout
is expected to be identical, but verify silkscreen labels on the specific unit before
wiring.
