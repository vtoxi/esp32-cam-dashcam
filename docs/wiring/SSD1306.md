# SSD1306 OLED ×2 (0.96" 128x64, I2C) — Wiring

**Status: Address conflict confirmed; gateway-side GPIO proposed (untested).** Both
physical units report the default address `0x3C`, with no address-select jumper found
populated. They cannot share one I2C bus as-is — see Section 9 for the resolution plan
(second I2C bus on the gateway).

## 1. Module Description

Two 0.96" 128x64 SSD1306 OLED displays, I2C interface, mounted on the gateway per
Section 25 of the project spec (page content per display is configuration-driven, not
hard-coded).

## 2. Voltage Requirements

- VCC: 3.3V–5V (most 0.96" SSD1306 breakouts have an onboard regulator; verify against
  the specific unit).
- I2C logic: 3.3V typical on these breakouts — verify.

## 3. Pin Table (per display)

| Pin | Connects to |
|---|---|
| VCC | 3.3V or 5V (per board regulator — verify) |
| GND | Common ground |
| SCL | Display 1: gateway GPIO 9. Display 2: gateway GPIO 11 (second I2C bus) |
| SDA | Display 1: gateway GPIO 8. Display 2: gateway GPIO 10 (second I2C bus) |

## 4. ESP32 GPIO Connection

Proposed: Display 1 shares the primary I2C bus (GPIO 8/9) with the MPU6050 at its own
address `0x68`, no conflict. Display 2 goes on a second I2C bus (GPIO 10/11) since both
displays are confirmed at address `0x3C` with no jumper available. Not yet bench-verified
— see `docs/wiring/ESP32_S3_GATEWAY.md` Section 11.

## 5–6. Power / Ground

Per Pin Table above; common ground with gateway required.

## 7. Communication Interface

I2C. Both confirmed physical units report address `0x3C`; no address-select jumper was
found on either board. Resolved via a second I2C bus on the gateway (GPIO 10/11 for
Display 2) rather than address-based sharing — see Section 3/4 above.

## 8. Pull-ups / Pull-downs

Standard I2C pull-ups (4.7kΩ typical) — verify whether onboard on these specific
breakouts before adding external ones, especially if sharing a bus with MPU6050 (see
`docs/wiring/MPU6050_HW123.md` Section 8).

## 9. Known Conflicts

Address conflict if no jumper is present on either unit — see Section 7 above.

## 10. Safety Warnings

None specific beyond standard I2C/3.3V logic precautions.

## 11. Testing Procedure

1. Run an I2C scanner sketch with one display connected, confirm address (`0x3C` or
   `0x3D`).
2. If a second display is added, re-scan to confirm both addresses are distinct (or
   determine a second-bus plan is required).
3. Run a minimal Adafruit_SSD1306 example to confirm display renders correctly on each
   unit before building the page system (Phase 13).

## 12. Example Configuration

Deferred to Phase 13 firmware implementation.

## 13. Board-Specific Differences

Some 0.96" SSD1306 breakouts use SPI instead of I2C (7-pin vs 4-pin) — confirmed hardware
for this project is the 4-pin I2C variant; if a differing unit is substituted later,
re-verify interface type before wiring.
